# PAtrick 详细设计

> 设计基线：2026-11-03 的 [PAtrick 技术方案](PAtrick技术方案.md)。本文把选型转为可以实现、恢复和验收的行为；已写出的接口与行为仍须由 [验收证据](../acceptance.md) 证明。技术方案中的 `PAtrick需求文档.md` 当前未提供，本文不为它虚构需求。

## 1. 交付边界

第一条工作链是：同步空间的一个 `productIdeas` 目录发生变化，服务取得同一产品的有效事实与本人标准，判断应归档、可自动修改 PRD、还是确需本人取舍；在需要时完成中英文查证并只问一次；随后规划、隔离执行、独立检查、创建 GitHub PR、验证当前 head 的可信必需检查、合并并读回正式 PRD，最后把真实回执与反馈送回发起方。

首版的配置只允许一个产品、一个目标仓及明确的 PRD 路径。新增但没有证据的想法归档为待验证假设。界面、Obsidian 或 IDE 关闭均不改变任务生命周期。开发运维和知识学习复用相同的来源、角色、权限、回执和反馈契约，只有经过逐条真实验收的来源与动作才能显示为已覆盖。

有三种不同的就绪结果：

- **代码验证通过**：类型、单元测试、禁写回放和界面测试均有本次运行记录，可以用替身验证完整链路。
- **外部前提就绪**：真实仓库、可信 CI、飞书本人身份与历史权限、后台模型额度、隔离和业务网络均有准入记录。
- **真实工作验收通过**：在获准真实仓分别完成零问与只答一次的交付，保存角色轨迹、CI、合并 SHA、文件读回与消息回执。

这三项分别记录。模拟适配器、绿色按钮、worker 自述或一条本地成功命令都不能代替远端交付证据。

## 2. 部署与模块

自有代码是一个 Node.js 24、TypeScript ESM 项目。Hono 输出服务端 HTML；普通 JavaScript 只增强轮询、抽屉、筛选和表单，关闭 JavaScript 仍能导航、查询与提交答复。SQLite 使用 `better-sqlite3` 和 FTS5；Zod 校验外部数据；Vitest 验证行为；Playwright 验证浏览器流程。首版没有消息服务器、图数据库、向量库、Python 服务或前端构建框架。

模块边界如下，名称也是实施时的所有权边界：

- `src/domain.ts`：共享 Zod Schema、版本化数据类型、状态、稳定编号及摘要规则。所有跨模块和跨进程数据均由这里的 Schema 接纳。
- `src/config.ts`：启动配置、目录与路径规范化、域/项目/本人身份、角色准入、额度和自动写入策略。无有效配置时只运行可证明安全的本地查看模式。
- `src/store.ts`：数据库迁移、事务、任务账本、收发箱、尝试租约、唯一约束、读视图、备份快照。
- `src/intake.ts`、`src/collector.ts`：统一 `SourceRevision` 入账与失效；Chokidar、文件稳定读取、补扫和水位由 collector 驱动；消息来源走同一入账入口。
- `src/knowledge.ts`：结构化证据解析、候选引文核实、Markdown 事实/知识/经验卡发布、FTS5、权限内 `lookup`、撤回和重建。
- `src/standards.ts`：明确决定建案、观察与原则区分、规则版本/范围/例外/冲突、留出案例评测。
- `src/reviews.ts`：引用结果材料的严格 Schema、当时初判的到期复核、当前有效结果视图；复核不推进执行或修改原则。
- `src/scheduler.ts`：一次一个 worker、角色准入与次序、冻结输入、超时/费用/尝试隔离、自动切换通知。
- `src/orchestrator.ts`：从来源到反馈的持久状态推进、阶段版本绑定、返修与恢复；不直接持有平台凭据。
- `src/integrations/workers.ts`：Grok Build 非交互 CLI、dsh ACP、`codex exec` 适配器及统一结果校验；进程失败与业务失败分开。
- `src/integrations/research.ts`：只读中英文检索与原文读取、独立来源归并、检索出域限制、证据充分性。
- `src/integrations/github.ts`：凭据边界内的 GitHub App 写入、PR 与检查对账、合并及文件读回。
- `src/integrations/gitlab.ts`：与 GitHub 同义的 MR/流水线/合并/读回契约；首条工作链不因文件存在而宣称已验收 GitLab。
- `src/integrations/feishu.ts`：官方 SDK、已验身份的消息/卡片/历史补读、发件查重与主动私聊。
- `src/mcp.ts`：官方 MCP SDK 的 stdio 入口连接常驻 HTTP 服务，暴露项目内查询、提问、按编号取答和受管工具记忆读取，不另开数据库写入者。
- `src/integrations/network.ts`：只探测已配置业务路径、心跳、诊断与受控 VPN 修复，不把网络异常混为鉴权异常。
- `src/app.ts`、`src/auth.ts`、`src/readiness.ts`、`src/web/`、`public/`：认证 HTTP 边界、只读 `TaskView`、配置就绪状态、HTML 和渐进增强交互。
- `src/runtime.ts`、`src/index.ts`、`src/mcp.ts`：组合模块、独占运行目录与本地令牌、HTTP/后台和 MCP 启动、定时补扫、恢复、信号处理；它们不承载业务判断。

数据库、WAL、仓库凭据、进程日志、临时任务副本和备份口令放在同步空间外。Vault 和获准业务文件可以同步。Mac mini 是规范 Vault 的唯一发布者，其他机器上的编辑再次作为来源进入采集。接管须先吊销旧写入资格；进程内互斥不能替代写入者资格。

## 3. 契约与权限

`src/domain.ts` 是字段名称与枚举的唯一契约来源。以下是不随实现命名变化的语义要求；字段合并不得丢失约束。

- **来源修订**：Schema 版本、稳定来源身份、授权域、项目、平台、原对象 ID、原始修订、内容摘要、原文定位、作者、接收时间、有效时间、留存方式，以及更正/撤回关系。实时事件、历史补读和文件镜像只有在能证明同源时才共享稳定键。
- **证据引用**：来源 ID 和修订、原句、可重读定位、作者、核实状态、权限及有效期。来源的存在只能证明该作者说过这句话，不能直接证明主张为真。
- **事实/知识/经验卡**：稳定 ID、版本、类型、项目与授权域、陈述/主题、有效状态、精确引文、依据、冲突、反例及失效条件。经验卡另需环境、代码版本与测试/CI 回执。
- **决策案例/规则**：原始决定 ID、已核本人、事项范围、生效区间、冻结目标与候选、原话、已知或未知理由、支持/反对案例、规则版本、采用任务及后续结果。`观察`、`外部参考`与`本人明确原则`是不同来源类别。
- **DecisionSnapshot**：`schemaVersion: 1`，任务/版本、成功尝试 ID 与 `inputHash`、来源/修订、`goal`、完整 `decision`、实际采用的 `rules` 内容与版本、`sourceRefs`、`expectedOutcome: string | null`、可选研究记录、`recordedAt`，以及可选冻结 `reviewAt`/`reviewIntervalDays`。原判及规则中的引文随快照保留，不在回看时按规则 ID 读取最新版。
- **任务与尝试**：任务 ID/版本、输入修订集、阶段、冻结上下文摘要、角色、尝试 ID、实际 runner/模型/提供方、授权、预算预留/实耗、截止时间和租约。输出必须回显任务版本和当前尝试 ID。
- **Decision**：归档/执行/待补证/待本人决定的判定，依据、规则及版本、未知项、推荐和预测。`expectedOutcome` 在输出 Schema 中是可选的 `string | null`，兼容旧输出；宿主快照把缺省值规范为 `null`。worker 只给建议，宿主另做动作授权。
- **ExecutionPlan**：目标、需求版本、仓库与基线、步骤、允许路径、测试命令、停止条件与摘要。执行结果绑定方案摘要、基线、补丁摘要及测试记录；检查绑定同一组内容。
- **问题与答复**：问题编号、任务/卡片版本、发起工具/线程、本人、适用范围、A/B 冻结文本及证据、C 原话、答复平台原 ID、接纳结果与接纳时间。`Task.decisionSnapshotId` 引用当前初判，`Question.decisionSnapshotId` 固定该问题当时的初判；`DecisionCase.decisionSnapshot` 保存其副本。
- **CaseOutcome**：`id`、实际 `receiptId`、`recordedAt` 和反馈 `summary`，在 `DecisionCase.outcomes` 中追加；它表示该回执支持的交付反馈，不自动证明产品指标变化或预测成真。
- **交付回执**：目标仓、PR/MR、当前 head、检查名及可信生产方、检查结果、检查时间、合并 SHA、正式路径、该 SHA 的读回内容摘要与时间、原任务反馈回执。
- **TaskView**：仅含调用者可读的状态、最后进展、等待原因、问题、证据链接、故障与建议。它不带 token、环境变量、未授权原文或 worker 命令全文。

所有入库、检索、模型调用、答复、通知、仓库写入和输出都检查当前授权。有效权限是本人/调用工具、数据域、项目、来源留存和出域规则、角色、模型提供方、允许动作与路径、有效期及剩余额度的交集。缺失、未知、冲突或过期均拒绝自动动作；配置声明不能代替该机器和提供方的实际准入记录。

权限至少在四个时间点重验：来源正文入库前；派工或检索出域前；写 PR/MR 或合并前；回送原文/证据前。任务创建时获准不代表稍后仍获准。`ephemeral` 正文及可读派生内容只在当前进程保留，不进持久快照、Vault、FTS、长期日志或消息归档；磁盘只留必要的脱敏运行标识。永久任务的初判引用和适用规则须排除临时来源证据，不能通过快照或案例把临时证据转成长期内容。

## 4. 持久账本与副作用

SQLite 事务同时写入业务状态、事件和待执行动作。动作编号从任务/版本、动作类型、目标对象及语义摘要稳定生成；状态更新使用版本比较，事件、来源修订、答复接纳、卡片发布和外部动作分别有唯一约束。不可用内存队列作为事实来源。

逻辑存储包含：来源与水位、任务与状态事件、worker 尝试、角色准入和预算、收件箱与双路投递、发件箱与远端回执、事实卡与引用边、案例与规则版本、研究记录、问题与答复、外写动作与交付证据、复盘/评测、写入者资格及维护指标。FTS 是可重建索引。

外部动作统一按以下顺序运行：

1. 在状态事务中登记意图、稳定编号和目标；先提交，再联网。
2. 读取当前授权和版本；锁定该意图，核对是否已有可信远端回执。
3. 未执行且有证据支持重试才执行。发件按目标线程、发送方、稳定标记查重；PR/MR 按仓库、分支和稳定标记查重。
4. 保存远端对象、版本和证明，再推进状态。远端结果不明则进入对账状态，暂停新的外写。
5. 超时、进程死亡、网络断开或机器重启后，先重新读取远端，确认已有、未有或仍未知。不能把“请求超时”解释为“没有发生”。

文件系统与 SQLite 无法组成原子事务。卡片发布先登记意图，在同文件系统写临时文件并原子替换，再登记文件摘要与发布状态、更新 FTS。只有已发布且回读摘要匹配的版本对外可见。启动恢复按意图和文件摘要补全，重跑不会生成第二张卡。单写入者下仍保留双方冲突版本，不能静默覆盖用户编辑。

启动恢复先加载撤回与权限变更，再处理过期租约和未决远端动作，最后恢复普通派工。一次只接纳当前尝试的输出，旧进程即使晚到也不得推进任务。轮询间隔、退避和下一次探测时间均落账，任务不会因页面刷新重复启动。

## 5. 来源、知识与标准

### 5.1 采集

文件监听只表示“可能有变化”。等待稳定后，确认规范路径仍在允许目录内、不经符号链接逃逸，读取一致快照并计算内容摘要；未入账不推进水位。定时扫描比较目录清单与已知修订，补足漏通知、修改和删除。无法稳定读取的文件重试并在来源页显示原因。

消息先持久接收，再分别投递“续办原任务”和“采集来源”。其中任一路失败单独补办，不让本人重答。已订阅讨论的新消息直达原任务。本人答复可以同时续办与形成案例，但机器人通知、回执和注入的记忆不得回流成新原则或新采集循环。

更正或撤回先使依赖的事实、规则、决策和待办失效，随后重算。按当下权限清理正文、摘录和索引，保留获准撤回标记，避免扫描/备份恢复再次发布旧资料。迟到、身份未核或过期卡片答复只留允许的审计结果，不提升为本人原则。

### 5.2 事实与检索

结构化 PR、SHA、CI 回执由程序解析。自然语言由 `knowledge_extract` 提出陈述、引文、解释和关联候选；宿主回读指定修订，逐字核验引文及上下文，再发布 Markdown。业务结论缺少权威记录或独立证据时保留“待核”。知识卡围绕主题链接事实、冲突和反例；解释和推论标明依据。

FTS5 使用 `unicode61`。索引与查询都抽取连续中文的相邻双字词，保留英文词项与项目别名；“草稿恢复”至少能按“草稿”“恢复”找到。查询先限定调用身份、授权域、项目和当前有效版本，再按 `bm25()` 排序；返回前回读 Vault 原句及出处，二次核对撤回和权限。未知项目返回空结果。零结果可说明缺口，不能越域补齐。

索引删除后可从已发布 Vault 与最新撤回记录重建。停用模型或关闭 Obsidian不影响已发布内容检索。未验证的经验卡仅供查看，不能作为下次自动执行的可靠解法；只有第五层回收测试/CI 等证据才能改变核实状态。

### 5.3 本人标准

`orchestrator.ts` 接纳成功 `decide` 输出并校验当前引文与规则后，在同一事务调用 `recordDecisionSnapshot(store, task, input, decision)`。该函数核对成功尝试的任务/版本及 `inputHash`，只复制 `decision.ruleIds` 实际采用的规则完整内容，并检查它们在派工期间没有变化；规则已变则拒绝旧判断、暂停任务，显式重试后按最新规则重新判断。快照写入现有 `actions` 账本，`kind: 'decision.snapshot'`、`status: 'completed'`、`payload.snapshot` 保存 `DecisionSnapshot`，不另建一套判断存储。

Task 和 Question 保存快照引用；本人接纳 A/B/C 时，`recordOwnerDecision` 校验问题引用的任务/来源/域/版本，再将该快照复制到 `DecisionCase.decisionSnapshot`。即使任务答复后增版并重新初判，旧问题和案例仍保留当时原判、目标、实际规则内容/版本、引文及预测。A/B 登记当时所选建议的冻结文本，C 登记本人原话。未明说的理由和缺少历史快照的原判明确未知，不能用当前规则或后来的反馈倒填。

CLI 的 `expectedOutcome` 为可选兼容字段；当前提示要求输出带不确定性的明确预测，未知则为 `null`。快照的 `expectedOutcome` 始终为字符串或 `null`，缺省不补写猜测。`feedback` 阶段必须先取得并验证真实 `DeliveryReceipt`，再调用 `appendCaseOutcome(store, task, receipt, summary)`，按案例 ID 与 `receipt.id` 形成稳定键追加到 `outcomes`，相同回执重试不重复追加；旧 `outcome` 字段仅保留兼容摘要。预测与基于回执的交付反馈分开，业务效果仍需要独立可观察结果，后来结果不能回写成当初已知。

撤回经 `intake.ts` 清除相关快照 action 的可读 payload、案例快照/结果、问题和任务派生内容；`store.ts` 的发布与恢复同样遵守撤回记录，保留允许的回执审计而不复活旧原文。临时任务的快照、问题和结果只在进程内可读，派生案例不落盘；永久任务不能引用临时来源或含临时引文的规则。

`case_extract` 对 PRD、评审或讨论提出候选；宿主核验原始决定和修订、本人、范围、例外、反对证据，按原始决定去重。一次选择先只适用于该事项；只有本人可核原话明确扩大范围，才扩大原则范围。反复猜中、模型概括和行业惯例均不得自动升级为本人原则。

明确改主意形成有生效时间的新版本；局部例外保留基线；证据冲突保留两侧且暂停自动引用。撤回、过期和适用冲突立即使相关规则不可用于新初判，并让本域未决任务重新判断。决策保留引用的规则版本、预测和后续实际结果，个人偏好一致度与业务效果分别报告。

### 5.4 初判到期与结果材料

项目 `reviewIntervalDays` 是 1–365 的整数，默认七天；JSON 配置和新增项目表单使用同一校验，设置页显示保存值。`recordDecisionSnapshot` 使用实际成功判断输入中的项目周期，冻结 `reviewAt = recordedAt + interval` 和 `reviewIntervalDays`。旧快照缺字段时独立使用七天，不从当前配置重算。原判、目标、规则版本和未知预测均不改写。

结果材料通过已认证的 `POST /api/reference-sources` 导入为 `reading`、`purpose: reference`，沿用项目/域、来源修订、原文定位、显式留存和撤回契约，但不创建执行任务。重复引用仅一份；同修订更换用途拒绝。Vault 恢复以恢复前账本中来源用途或同项目/域/修订的真实任务关系为执行依据，编辑前置元数据不能把引用变为任务。有效普通来源先恢复，特殊 owner-answer 随后核对可信 SQLite 已接纳问题、本人/任务/版本、当前主来源及精确答复；两者文件名顺序不影响合法恢复，投影不能补造已接纳问题。

宿主生成的 Vault 编辑来源保存 `parentSources` 修订关系，包含案例的本人答复和当时快照依赖；旧账本副本只从可信实体路径补回关系，不采信可编辑 ancestry。父来源更替或撤回使历史、嵌套及案例副本失效，并清理可读证据和复核派生物。缺 SQLite 行时，身份不匹配/不可核的来源、或没有可信祖先关系的 Vault 副本仅恢复成无正文的 withdrawn/reference 墓碑，不发布可读原文、不派生任务；篡改 kind/externalId/revision 不提供授权。

`POST /api/judgments/:id/evidence` 接受 correction/metric/failure/abandonment 和当前来源精确引文；宿主绑定原始成功判断、任务、本人、项目/域、来源作者与记录者，调用方不能指定身份或记录时钟。metric 仅从逐字引用的严格 JSON 解析：`schemaVersion: 1`、名称、有限数值、单位、开始/结束时间，可选有限基线与正整数样本数。无样本数保持未知。观察不得早于判断或晚于宿主当前时间，测量开始不得早于判断，结束时间等于观察时间；非 none 的来源报告归因必须另有当前同域精确引文。永久判断拒绝临时来源，临时可读派生物不落长期磁盘。完整请求/响应例见 [运行手册](../operations.md#outcome-review-sources-and-http-contracts)。

证据写入现有 actions，`kind: decision.evidence`、`payload.evidence`，稳定键含快照、类型、来源修订及引文摘要。相同重试回原记录，冲突元数据拒绝。复核写 `kind: decision.review`、`payload.review`，包括当轮时间、当前证据/修订、可核交付回执 ID、绑定该快照的本人选择、实际方案测试失败、执行状态及缺口。worker 的独立检查 Review 与结果复核分开。后续选择不能泄漏到同任务另一快照，工程失败、连接阻塞、取消和归档也不冒充产品失败。

宿主在接纳 execute/check 的有效结果后、返修替换缓冲前，把失败的方案测试写为去重的 `decision.tests` action，包含初判快照、任务版本、成功接纳的 attempt/inputHash、阶段、计划命令、失败输出和时间。复核按这些绑定回读，重规划后的实际执行版本仍归原快照，其他判断不借用；传输故障不进入测试失败历史。旧版仅能保守采用同版/同快照当前缓冲，修复前已被覆盖的失败无法恢复，不推测补写。

运行时启动后及每 60 秒以宿主时钟扫描当前本人项目；范围查询 `GET /api/reviews?project=…&domain=…` 不写账，显式 `POST /api/reviews/run` 只接受项目/域并使用服务器时间。扫描不联网、不调用模型、不改任务/规则。未到期不写；当轮稳定键含快照/轮次/输入摘要，未变输入跨重启不重复，有新有效材料可追加不可变报告，不以后来材料回填错过的轮次。定时扫描异常仅固定脱敏日志，下分钟再试；显式调用仍返回错误。关闭先清 timer 再关 Store。

缺可核交付、当前测量、已知正样本、交付后测量区间或非空归因引文时继续 `observing`。只有满足关联条件才显示 `evidence_linked`，含义是已关联来源报告的结果依据，不是因果、预测准确或业务改善认证，更不自动提升原则。目前未配置真实指标来源，业务效果继续待观察。来源修订/撤回立即使旧材料和旧报告不能作为当前依据；允许的历史审计与可读内容清理分别处理，重启/重建不得复活。没有当前报告表示回执待复核，不等于没有交付。

## 6. worker 调度与闭环

当前本人政策仅允许 Grok/Codex 已有订阅所含额度，不追加计费。账户实际后台权益与付费溢出控制仍未核验；本地费用预留/预算不构成额外支出授权，局部试运行不授权真实模型调用或提供方准入。

每个 runner/角色/数据域/模型提供方组合独立准入。准入回放证明版本化输入输出、数据出口、工具权限、费用与隔离；无至少一个已准入备选就不能声称自动切换已验收。生产一次只跑一个 worker。

角色候选次序固定：

- `knowledge_extract`、`case_extract`、初判及默认执行：Grok Build → dsh → Codex。
- 明确配置 dsh 执行：dsh → Grok Build → Codex。
- 规划、检查、反馈：Codex → Grok Build → dsh。

先按当前数据域、角色、权限、提供方、预算筛选，再依次尝试。检查优先选择不同于实际执行的 runner；同 runner 只有预先验证的独立只读配置才允许进入检查候选。规划与检查独立只读，执行测试的代码仍在隔离副本运行。

启动失败、超时、持续限流或凭据失效属于运行器不可用，可换手。测试失败、补丁问题、检查不通过属于业务返修，不借切换绕过问题。每轮每候选最多一次；全部不可用时保留任务、安排退避探测并通知本人。新尝试继承冻结输入，拥有新的尝试编号；旧输出被拒收。

每次实际切换在创建新尝试的同一事务里创建飞书通知意图，包含任务、角色、原 runner、新 runner、原因和是否续办。通知失败由发件箱补送并按切换编号去重；它不进入“等我回答”，不阻塞健康 worker。

阶段转换遵守以下不变量：

1. 初判只能引用当前有效、获准且有出处的事实和本人规则；纯新想法归档假设。
2. 需要本人时先研究；证据足够可直接处理，只有取舍才进入等待。
3. 规划冻结需求版本、基线和路径；宿主验证授权、步骤、测试和停止条件后才能执行。
4. 执行仅输出隔离区补丁、测试记录和问题，不持有仓库写凭据。
5. 检查核对相同需求、方案摘要、基线和补丁，必须含独立测试。返修最多两轮，受任务总预算约束；基线或方案变化重新规划和检查。
6. 写入器重新核对来源与权限，创建/复用 PR，要求必需检查名和可信 App 列表都非空，等待当前 head 可信必需检查逐项成功。零项、缺项、跳过、未知生产方或 SHA 不符均不能通过；模型输出永远不能充当 CI 或合并证明。
7. 基线/head 变化使旧检查和审查绑定失效；合并前重新核对。仓库要求独立人审时不绕过，链路显示未就绪或等待仓库所需步骤。
8. 合并后按合并 SHA 读回正式 PRD，核对内容摘要与预期变更。回执交给反馈角色，登记并回送原任务；失败继续保留未完成和重试状态。

“归档假设”“等待本人”“技术阻塞”“已交付”分别有依据。技术阻塞显示在任务旁；没有真实合并和读回证据不能显示为已交付。

## 7. 双语研究与 A/B/C

研究输入只包含获准出域的词。中文、英文分别实际查询问题、备选、反例或失败情形，打开原文，记录检索词、语言、URL、发布日期/抓取时间、适用条件、矛盾点、原始发布者和独立来源归并键。搜索摘要不代替原文；翻译、镜像和转载不构成第二个独立来源。

优先取得两种语言的一手资料，找独立来源交叉核对。某语言缺少可靠结果就换词并记录缺口。有两个可行建议但仍有不确定性时可明示缺口发卡；不能支持两个可行建议则保持待补证、退避重试，不能捏造第二个方案。

决策卡只有三个入口：A 首选建议、B 第二建议、C 我自己决定。A/B 均冻结具体做法、适用性、收益、代价、风险、可逆性、个人标准和证据；C 接受自由输入。卡片绑定问题、本人、发起工具、任务与来源版本。等待时释放 worker；本人不答复就持续等待，不设置自动代选超时。

答复由宿主核验身份和当前问题/卡片/任务版本，A/B 采用冻结文本，C 保留原话及范围。在同一事务中接纳一次、登记续办动作和获准来源；同事件重放不重复唤醒。旧版答复使任务重新判断，不执行过期选项。未认证者或跨项目工具无法回答。

飞书应用认证的 WebSocket/发送/历史配置需要应用 ID、secret 和已核本人 Open ID，私聊 Chat ID 与成功的授权历史补读仍是通道门槛；启动先补读再建立 WebSocket。HTTP verification token 仅对 HTTP 回调必需，缺失、空串或纯空白时在挑战、签名/解密与派发前拒绝 403；即使 WebSocket 已就绪或请求已签名/加密也不放行。配置加密回调时保留 encryption key、请求时效、签名与原始正文绑定。设置和 doctor 只描述连接配置，不代表实际双向业务验收。

正常本人业务路由把 `/pair`（含前导空白、大小写及换行）保留为配置输入并忽略，实时/历史重放不创建来源、任务、案例、规则、卡片或发件，持久接收元数据只含允许的 ID、摘要、时间与空来源列表，不保留命令正文。本人/私聊/项目/域/出域与撤回检查保留。私有一次性挑战工具不是已交付的通用配对 CLI/API，不以首个发信者认定本人；手动私有环境设置仍受支持。

飞书从本地文件发起的任务也主动私聊本人；离线按水位补读。工具可断开后按编号取答；回送仍检查原发起方与项目权限。MCP 不能把调用者传入的项目名称当作已认证身份。网页答复走相同收件和接纳服务，表单需要私网认证、会话校验和防跨站请求保护。

## 8. 工作台

视觉采用暖象牙白底、森林绿主色、克制边框和排版。左侧栏是工作台、知识、规则、来源、活动、设置。桌面工作台三栏分别是“正在处理”“等我回答”“建议与结果”，每张卡优先显示产品、任务意图、最后进展与下一步；时间、角色和故障作为辅助信息。数字必须来自账本，不使用演示数字冒充运行状态。

点任务打开右侧抽屉，包含版本、证据、阶段轨迹、实际 worker、问题与回执。等待栏内直接显示 A/B/C，A/B 可查看依据，C 展开文本框。提交成功显示已接纳或版本过期结果。普通切换通知只在活动和任务轨迹出现。

判断标准页增加“结果复核”，按快照独立显示目标、初判、冻结周期、到期状态和当前缺口，分别列交付、更正、测量、工程失败、放弃；“已关联结果依据”旁保留非因果/非预测认证说明，不增加日常手工标签流程。来源 reference 标记“结果依据，仅作引用，不启动执行任务”。

知识页可按主题/产品/状态检索并打开精确原句；规则页区分本人原则、观察、外部参考，展示范围、版本与反例；来源页展示最后修订、补扫、撤回和覆盖状态；活动页是可过滤的审计轨迹；设置页显示外部准入、费用和路径状态，并隐藏凭据。通用 state、来源撤回、任务/问题与查询 API 同样验证当前项目本人，聚合状态排除其他本人项目。暂无任务时给出明确空状态，未配置外部依赖时显示真实未就绪原因。

所有交互可用键盘操作，具有清楚标签、焦点、状态播报和足够对比度。小屏改为单列并保留三类任务分组，抽屉成为全宽详情。轮询读取 `TaskView`，不触发任务执行；导航和答复在无 JavaScript 时保留完整 HTML 表单流程。HTTP 失败显示可重试状态且保留 C 的输入。

## 9. 运行、安全网络与恢复

Mac mini 的生产计划保持不变；当前 MacBook Pro 的局部 Lima 试运行不替代生产验收。宿主 Lima 传输仅保留 PATH/HOME/TMPDIR 与显式可选的 `LIMA_HOME`，CLI 和 ACP 共用该边界；未设置时沿用 Lima 默认 home。私有安装需在服务 PATH 提供对应 `limactl`，并使用创建实例时相同的已审 home；不转发通配 Lima 设置、代理或凭据。模板保留 2.3.0 最低版本与隔离项，稳定版 2.2.1 缺 `hostLoopback` 支持，开发构建须固定官方来源并验证，不能伪称已发布 2.3。操作前提见 [主机部署](../deployment.md#lima-worker-isolation)。

Mac mini 用 launchd 拉起业务服务和本机网络守护器。worker 位于 Lima，移除默认挂载、禁用 SSH agent 转发，仅挂载该任务获准材料或任务副本；限制出口和会话日志上传。写入器在 VM 外独占短期仓库凭据；worker 环境变量不继承主机凭据。Mac Pro 用于开发/恢复；网页走认证私网，手机走飞书。公司正文和凭据留在获准设备及网络域。

每分钟向获准对端发心跳；业务目标不通也触发诊断。顺序是本机网卡、DNS、路由、代理、TLS，再判断对端；内网探测前先验证企业 DNS/路由。鉴权失败、限流和强制 MFA 各有独立状态，MFA 只通知本人，不无限重连。

网络修复以业务路径加锁，限定次数并退避，只操作故障路径。Tunnelblick AppleScript 或已安装 OpenVPN 的获准管理接口处理内网；GitHub 由经本机验证的 Shadowrocket 状态/连接/断开快捷指令处理。修复后同时验证故障路径、原健康路径与心跳，成功后先核对未决远端动作再续办。没有已验证命令或企业授权时保持挂起。

双 VPN 只有在企业允许分流、两种启动顺序、并发与单路重连全部证明企业 DNS/路由和 GitHub 出口正确后启用。优先使用获准的进程代理；冲突时分设备；只一台且允许轮换时排空写入再切换。不得因为一般公网可达就宣称内网路径正常。

每天使用 SQLite 在线备份生成一致快照，再用 restic 加密备份数据库、Vault 版本和撤回记录到获准异机。恢复演练先重放撤回、检查权限与远端动作、吊销旧写入资格，再恢复调度。仅复制活动数据库文件或依赖网盘同步不能证明可恢复。

## 10. 扩展与持续校准

首版受管 Codex 任务启动前以认证项目身份取少量有效卡片、版本和出处；结束后只采集获准新对话，按原会话/轮次/修订去重，剥离注入内容。Cursor 的启动摘要和后续 MCP 查询单独验收：用只有试点卡含有的标识证明工具实际取得并引用当前版本，撤回后新会话不能再取得。未验证逐轮 hook 不宣称支持。

默认不复制第三方代码。若移植 Super Agent `6337fc8` 的稳定键/恢复样例，保留 MIT 声明、固定来源与改动；若移植 memhub v0.2.3 的解析/游标样例，保留 Apache-2.0、固定来源与改动。不能把 `private` 上游包当可直接依赖的公开 core。移植总投入最多四小时，拖慢链路时只保留协议与故障样例。

开发运维从已合并 PRD 触发，绑定同提交测试、GitHub PR 或内网 GitLab MR、发布后错误率与回滚。知识学习从已获准的 X 书签或阅读信号开始，输出解释、关联、反例和到期复核。无自动入口的公众号、微信或第三方 Grok 显示未覆盖，不给日常操作添加转发、贴标签或导出。

每周记录漏采、错误引用、漏问/误问、真实交付、费用、维护分钟和一个可复盘案例；连续两周维护超过 60 分钟就停止扩源。每月用隐藏本人原答案和事后结果的同域留出题对照旧版与候选，区分偏好、业务结果、关键漏判、纠正次数与样本数。只在同预算至少修好一道原错题、关键题不退化、越权/重复外写/假交付为零时，在证据覆盖的单产品试用；异常自动回退并对账。个人价值取舍的变化仍需本人真实决定。

只有真实同义、多跳或历史题反复漏召回，才比较 FTS5 与 memhub 混合检索。试验独立存储、只读获准冻结主本，候选数、资料截止和预算相同，测出处命中、越域、撤回、错误原则、费用和维护；通过后也只返回候选卡 ID，最后由宿主回读验证。
