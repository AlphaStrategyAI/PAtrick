### Issues

#### Critical

**C1 — A different attached Vault consumes the original Vault's durable cleanup intent.** `src/store.ts:985–1006,1160–1161,1185–1193`; `src/backup.ts:43–59`; `src/store.ts:641–645`. A redaction cursor records scope, table and ID, but no binding to the Vault which may contain the prior projection. After a committed publication failure, opening the same ledger with a different empty Vault replays the job there; `publish` returns successfully because that path does not exist, and `flushVault` deletes the cursor. A later backup selecting the original Vault sees no pending cursor and copies the stale projection. **Demonstrated synthetic sequence:** one card redaction cursor before reopening became zero after reopening against a different empty Vault; the original card still contained the marker and a newly created backup succeeded with the same marker. The attached-matching and no-Store-Vault tests do not cover this ordering. Bind pending cleanup to the originating authorized Vault, or fail closed until that Vault is positively reconciled; never let absence in an unrelated Vault acknowledge it. Preserve idempotent matching-Vault recovery, foreign-path protection and no-authority-from-Vault semantics.

#### Important

**I1 — First G8 migration destroys recoverable, unambiguous G7 identity metadata.** `src/store.ts:110,913–915,943–950,1012–1017`; `src/intake.ts:201–204`; released before-copy `.superpowers/sdd/knowledge-experience-g8-integration-before/src/store.ts:393–395`. Released G7 persisted an ephemeral source with blank content but raw external ID, revision, author and locator. The new startup migration creates an opaque binding only if `source.content` is nonempty, then hashes even non-hash-shaped raw identity fields without recording their binding. Exact re-ingestion subsequently fails because every untagged row returns false from `sourceIdentityMatches`. **Demonstrated:** a synthetic source row recreated the exact G7 blank-body/raw-identity shape with four non-`sha256:` fields; after startup the binding was absent and the exact authorized input returned `revision_conflict`. This is distinct from the correctly fail-closed case where preimages were genuinely lost or raw digest-shaped values are ambiguous. Preserve independently sufficient existing raw host bindings before sanitizing, while continuing to reject ambiguous values, wrong metadata, revoked replay and old-observation backfill.

**I2 — Ranking stops before eligibility filtering can satisfy the requested result limit.** `src/store.ts:602–616`; consumers `src/app.ts:99–103`, `src/mcp.ts:20–23`, `src/orchestrator.ts:418–425`; test `tests/integration/experience-retrieval.test.ts:55–73`. The loop considers at most 1,000 ranked FTS candidates, then returns even if none were eligible. If 1,000 higher-ranked pending or otherwise ineligible cards precede a valid permanent or active temporary history, a search with limit 1 returns no result. This is a deterministic boundary consequence of the code, not a measured live incident or an executed 1,001-card probe. The >30 test is meaningful but does not cover this boundary. The binding eligibility-before-limit contract has no approved 1,000-candidate exception. Retain bounded resource use without silently treating a partial candidate scan as the full eligible result set, and test both permanent and temporary candidates beyond the boundary.

**I3 — Case snapshots can disagree with their canonical host action while being retained and published.** `src/store.ts:724–733,750–789`; `src/intake.ts:23–31`; `tests/integration/experience-recovery.test.ts:655`. `validCaseSnapshot` compares identity fields and the set of source refs, and checks both snapshots' references for coverage, but never compares the embedded decision, goal, citation contents, rule contents or factual payload with the canonical host snapshot. **Demonstrated:** an actual host-created synthetic case was re-saved with the same snapshot ID and source refs but a different embedded decision summary; the host action still said `Canonical decision`, while the inconsistent summary remained in the case and its Vault projection. This is malformed/inconsistent private host state, not a claim that an editable Vault alone can forge authority. Bind the complete embedded frozen snapshot to the canonical action before retention, deferral or promotion; retain genuinely identical host cases and both authorized recovery orders.

**I4 — Independent candidate normalization can outlive a source's temporary transition and lose its reported-unknown origin.** `src/experience.ts:141–164,95–107,267–284,357–364`; `src/store.ts:824–831,1012–1019,1046–1055`. A permanent local observation may normalize an independently sourced ordinary card from `codeVersion: unknown` to the observed revision and persist it. If the separate observation source later becomes ephemeral, migration moves its observation and evidence link into temporary storage, but the ordinary-card pass only selects cards whose own source is affected. The normalized independent card remains durable. After restart the link carrying `versionBinding.reported = unknown` is gone; a fresh independent matching observation can be associated without that origin, causing inferred revision metadata to appear authored. **Conditional source-level finding; no new observation execution or readable-private-text leak was demonstrated.** CI heads are constrained to 40-hex values; the local observation schema accepts text, but no real non-hash producer was established here. Treat a retained safe hash separately from provenance, and preserve or correctly revert the unknown-version field with its original lifetime while still requiring fresh evidence.

**I5 — MCP `ask` loses the committed status and can create another task on retry.** `src/mcp.ts:11–14,25–28`; `src/app.ts:108–112,163–170`; `src/store.ts:583–599`. When another operation has left a busy privacy checkpoint pending, an MCP `ask` can reach `/api/tasks` and commit its new task. HTTP responds 503 with `{error, code:'privacy_checkpoint_unavailable', committed:true}` and no task ID. The MCP wrapper parses the body but recognizes only `knowledge_snapshot_unavailable`, then throws `PAtrick returned 503. Check the local host and scoped configuration.` The installed SDK catches that error and serializes it as an `isError:true` tool result containing only that text (`node_modules/@modelcontextprotocol/sdk/dist/esm/server/mcp.js:185–210`); the failed result supplies neither committed status nor the ID needed by `get_task`. Other owner-facing discovery might still expose the task. Because `ask` supplies no external ID and `/api/tasks` generates a new random one on every call, a caller retry can commit a second task. This is a conditional source trace; no MCP retry, model, reader or delivery replay was executed in this review. Preserve committed outcome and a recoverable task identity across this caller boundary, and give retries stable identity or an equivalent no-duplicate contract. Existing HTTP and reader tests do not cover this MCP mutation path.

**I6 — Same-scope unrelated sources and events still receive transition work.** `src/store.ts:151–175,446–452,498–500,898–904,1037–1044`; test `tests/integration/experience-recovery.test.ts:478`. Every source save builds the entire same-scope source map and calls `opaqueSourceIdentity`, which runs a separate SQL query for each source; a temporary transition also resolves every same-scope event's source without first consulting the affected set. Thus an independent source's transition has work proportional to unrelated same-scope history, and repeated source saves accumulate quadratic work as the scope grows. The test's `store.get('sources', ...)` spy does not count these direct SQL lookups. This is an asymptotic code finding, not a latency or SLO measurement. Share the row/binding data already loaded and avoid resolving unrelated event dependencies while preserving correct affected same-scope cases/jobs/cards, shared DAGs and nested-write cache invalidation.
