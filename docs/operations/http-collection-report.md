# RSS 与单网页采集（T18）

当前实现只从服务端按账户、资料域、连接器和规范目标批准的 URL 集读取；默认服务没有批准策略，浏览器不能提供自己的白名单。普通读取只有 GET，无凭据、Cookie、脚本执行或自动抓取条目中的链接。DNS 解析前后核对权限，在固定的公共地址连接，并核对实际 TCP 对端；HTTPS 继续核验受信证书。

采集页上的三条证据独立：预览回执、可信控制确认后的启用回执、首次成功采集。预览不会启用。频率、暂停、恢复和断开走同一个 T03/T17 确认流程，按来源版本更新。断开保留已采集证据；旧配置的在途结果和已过期进程的结果不能推进当前游标。网页保留原响应证据，正文变化才写新对象版本；RSS 按条目稳定键去重。

后台通过持久 SQLite 的版本与租约领取来源。仅当启动者显式同时配置服务端 URL 批准策略和 worker 时启动，不访问未登记的目标。本地测试用模拟公共 DNS/HTTP 传输、真实 Hono 和 SQLite；实际网络与部署须单独验证。默认间隔 15 分钟，可选 30 分钟、1 小时、6 小时及 24 小时。

默认只收录在审批预览后新出现或发生变化的条目；完整预览条目指纹随确认落库，页面只显示最多八个样本。没有预览的内部登记在第一次成功轮询时建立同样的基线。已存在的相同条目不会生成业务修订，原响应仍作为读取证据保留。预览显示重定向在内的精确许可地址；联网许可仍由服务端提供。

历史导入是独立确认操作。预览使用当前来源版本最近已核验成功采集的本地 RSS 响应，选择 UTC 左闭右开区间，按可核验发布日期、稳定条目键排序，在对象和含原响应证据的字节预算内取确定前缀；无可靠日期的条目不进入导入。预览和导入不重新联网、不跟随条目链接。T03 控制回执绑定账户、调用者、资料域、认证代次、来源配置版本、证据及计划摘要；最终事务再次检查，导入不会覆盖已存在对象、推进常规游标或派新任务，同一确认重放使用原回执。

正式部署仍须配置可信精确 URL 策略和后台进程，并单独核验真实公网 TCP/TLS 及持续运行。原始响应证据与业务修订分开：原响应可能包含预览时已存在的条目，默认规则只禁止为相同内容生成新的业务修订。后续首次看到的条目无法仅凭基线证明实际发布日期。
