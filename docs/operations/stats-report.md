# T19 统计验收记录

统计活动以本地权威域账本为输入。主人答复须有同账户、资料域、问题版本、任务代次和 Hub 权威答案 ID 的已核验回执；完成任务须有对应业务发布及其已核验交付回执；自动决策须有已提交事件、同域判断许可、已冻结判断标准，以及该任务根实际获准的确切输入修订。它复用 T12 对 T05 来源事件的权威绑定：任务根必须命中给 `source-work` 的准入事件，数据域、账户、对象和观察序号必须一致；历史统计不要求这个源今天仍处于启用状态。以权威 ID 消费重复记录，不把清卡、模型建议、飞书测试、编辑检查或新草稿计为业务事实。首条有效交付归入原窗口；同域补偿事件按序号修正原桶，重复投递不会恢复已撤销事实。

三种周期按指定 IANA 时区计算含今天的自然日。每项活动单独核验证据：覆盖必须对应当前作用域、T13 启动代次和双水位，且时间连续覆盖所选窗口的起点到快照的 `as_of`。如果在线窗口已经滚入新的本地自然日，旧证明不能覆盖新窗口；应返回未知直至该日本身取得核验观察。离线时保留原窗口、原 `as_of` 和当时已核验的数值。全部时间额外要求已验证生产者自数据起点起的完整历史。无证据或只能覆盖部分窗口时统计为未知，不影响经核验的存量和任务数。存量按当前生效标准 ID、可用知识 canonical ID 以及有实例的委托类型去重，活跃委托类型另外按权限状态和到期时间核对。底部数和列表使用同一 T13 投影代次、通知序列和双水位。数据追赶时保留同代次的最后快照，新代次尚未重放时显示未知；读取统计不写入业务状态。进度表每批最多消费 256 条作用域事件，事实和推进的输入游标同事务提交，只有追平权威水位才发布新统计快照。

本地 T19 测试覆盖纽约和多伦多的跨夏令时窗口、上海整日边界、跨域和跨账户失败、未核验与重复事实、回执写入略早于域事件、补偿重放、未知值、只读路由授权、委托到期、1,000 条更新的批次追赶、投影代次隔离。10,000 条隔离事实的 SQLite 查询计划按账户、资料域、指标和发生时间使用 `stats_valid_activity_window`，其中目标域七日窗口只汇总 2,500 条。固定负载配置在 `fixtures/perf/baseline.json`，慢订阅、生产延迟、WAL 和实际验收另在 T25 留证。浏览器隔离组合检查读取真实应用和 SQLite，分别测试三个周期、语言保持原时区、筛选跳转、断联保留快照，记录业务写入次数为零。

此文档不代替真实部署证据。当前没有自动导入生产覆盖证据的入口；未准入的生产者保持未知。只在隔离测试中使用合成的覆盖证明，不向真实账本写入。

T25 / T22 交接：覆盖写入须位于可信服务内部，由具体生产者提供证据。通过 AnswerGate 查明权威答案的连续历史、通过发布器/账本查明可重放的已核验交付，自动决策则先验证实际自动提交事务产生 `decision.committed`，再证明其历史连续。记录清晰的保留起点、可观测的截止、账户/资料域、当前 Work 代次和双水位，并保存可复查证据摘要。只有已证明从权威历史开端覆盖时才能填写 `complete_history=1`；只调查当天不能证实过去七天。生产写入器应协调同一个观察截止时间：先核对生产者证据覆盖这个明确时间，再用该截止时间发布活动快照。通过已经准入的本机写入器提交 `stats_producer_coverage`，不得给公开端点、模型或任务配置权。不能用最早出现的事件、空库、时钟、Hub 连接健康、单个回执或配置开关作为覆盖证明。每次按生产者核对对应权威日志的缺口、重复、失败和更正；恢复需要新代次重新认证，旧证据不可继承。已经验证的数字应返回明确的时间跨度。
