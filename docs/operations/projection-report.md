# T13 工作与健康投影

`/api/v1` 下的工作列表、详情、时间线、系统健康和 SSE 共用同一投影。工作列表的计数与分页、数据、通知游标在一次 SQLite 读事务中取得。客户端用该游标接续；权限、会话或归档窗口变化时重新取快照。T19 只把已核验覆盖范围内的空集合显示为 0；同步中或失去来源时保留已核验时间和已有快照，不能用占位字段推断业务状态。

配置服务时，使用持久 SQLite 路径和 `createApp({ databasePath, credentialDirectory, productViewHub: { hub, signal, onError } })`。`hub` 只需实现 Autoloop `HubStateReader`，读取已配置 Hub，不提供写入入口。默认引导实例不会启动生产观测器；没有配置或还没有观测结果时，相应状态为未知。`/healthz` 供进程存活探针；`/api/v1/system/health` 需要登录并限制在可读资料域。T23 负责安装器和后台服务的连接参数、凭据引用及实际启动，发布前用实机验证。

后台分批扫描有有效授权的资料域；输入未变化时跳过重复投影。准备阶段在只读事务中执行，提交前核对输入版本；工作变更、健康通知和检查点同批写入。工作完成只由对应域和代次的已核验交付回执证明。真实 AnswerGate 回执后等待补证不应误报数据缺失。SSE 每批重查权限，慢客户端达到 64 条或 256 KiB 时断开，可以从已收游标重连。

本地回归涵盖数据库写锁存在时的 30 个并发列表读、1 条和 50 条的查询量、不同作用域、批内同时存在的健康与工作更新、两个慢读缓冲上限、重连、归档和撤权。此证据不代替 T25 的真实部署负载、WAL 和运行延迟测量。
