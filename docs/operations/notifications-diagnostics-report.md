核验日期：2026-11-17。本地通知账本、维护装配、系统页摘要预览与诊断下载已具备自动化证据。测试使用临时 SQLite、本地服务及模拟投递端口，没有发送真实飞书消息；这些证据不证明真实租户可用。

## 当前实现

通知按账户、资料域、对象、事件版本和渠道去重。发送前复核账户认证代次、当前域属主授权、60 秒内的 Hub 观测、投影双水位、对象版本与状态、同版本已核验答复、凭据可用性和当前免打扰偏好。目的地必须是唯一且经过 T10 双向测试的启用绑定；配对、配置、凭据、连接代次或目的地改变均使旧意图失效。免打扰结束前已答复的问题最终成为 `superseded`，事件重放不创建替代意图，也不恢复业务执行。

领取、交付边界和结果分别写入 `notification_attempts`。四次投递预算只计入有 `handed_off_at` 的实际交付边界；`attempts` 继续保留全部领取历史，因此可大于四。最终围栏发现投影临时不可用或进入免打扰时，不消耗投递预算。提供方尚未通过围栏就报错，以及租约过期但账本明确未交付时，保留原领取记录并延迟重试原意图；已有交付记录的响应丢失或过期租约仍进入 `uncertain`，仅在同一投递键获得权威未送达证据后允许重试。未知结果不等于失败，也不触发新意图。临时投影不可用或新的免打扰时段保留已有重试时间。

`hubRules(command, { notifications: true })` 显式增加固定分钟维护规则“通知维护”，由专用 `patrick-notifications` worker 领取。服务通过 `notificationMaintenance` 选项装配有界、分资料域的扫描和对账；Hub run 与计划事件键持久去重，结果确认丢失后重放原维护回执。维护只注册当前通知和核对原投递，不推进业务阶段。固定 Hub cron 与专用 worker 的真实协议合约用例位于 `tests/contract/T04.test.ts`；本轮沿用上一轮证据，没有重复执行该协议用例。

现有工作状态、Hub run 的 `summary` / `error` 和 effect 的任意 `reason` 不能直接推断 `needsOwner`。明确的本地事实入口 `recordOwnerBlockerRequirement(db, principal, input, at)` 接受 `owner_input_required` / `owner_authorization_required`，绑定事实幂等键、账户与域、当前工作代次、工作修订、视图修订、当前认证代次、策略修订和仍有该域属主授权的调用者。入口验证这些版本后记录 `notification.blocker.requirement` 域事件；同键改义被拒绝，可以用新事实键明确清除本人介入要求。

生产维护现已调用 `publishPrOwnerBlockerRequirement`，从真实 PR 发布器记录的当前 `effect_receipts.status='conflict'` 生成本人介入事实。仅接受四种已经有明确生产分支的终止冲突：`fixed_branch_conflict`、`fixed_branch_changed_at_pr_send`、`approved_patch_conflicts_with_base`、`branch_contains_unrelated_changes`。来源必须仍关联当前账户认证代次、同域的最新工作代次、交付阶段、原意图和构建、当前尝试与 grant、仍有效的本人域授权、当前判断依据和未撤回的来源修订。工作/视图/策略修订与冲突回执的原因、时间和来源身份一起形成持久来源摘要。任意 blocked/paused、未知原因或自由文本不会被提升为本人介入。

首次发布该域事实后，维护等待正常产品投影刷新赶上新水位；不会手动推进水位或立即发送。生产消费及最终发送围栏均重新查询当前冲突来源并比对持久摘要，同时核对最新本人介入事实、权限、修订、时间与投影水位。原回执改变、来源停用、工作改换阶段或尝试、权限撤回、未来观测和当前本人明确清除均拒绝发送。非本人阻塞仍为摘要；已有摘要可在本人介入证据成立时使用原意图和投递键进入待投递。无需额外 `app` 配置或布尔回调。

恢复域还必须通过 `recoveryWriteAllowed` 的连接内运行时授权。事实写入、队列写入、领取及最终发送边界均检查恢复门禁；数据库中单独复制的 `open` 状态不构成授权。发送前撤回运行时授权时，未交付的业务领取与结果保持冻结，交付时间不落账，也不调用外部写入。已交付但结果未知的原投递仍可按同键做只读提供方对账，并记录其权威结果；这些结果不恢复发送权限。完全没有恢复状态的旧库继续使用既有路径。

系统页“通知”按当前属主域展示未过期、最新意图版本的粗粒度账本计数，并支持按事项类型合并的本地摘要预览。摘要不暴露对象、接收人、证据标识或正文；读取和预览不改变意图、发送尝试、命令箱、业务事件或 outbox。它表示待处理账本，不能作为对象已重新核验或消息已送达的证明。

`POST /api/v1/notifications/test` 复用 T10 的预览载荷、固定测试文本、发送处理器与幂等回执。服务仅在明确提供 `feishuCredentials` 和 `feishuTestOutbound` 时接入授权测试端口，发送还要求持久数据库；通用会话凭据不被自动认作飞书凭据提供方。未装配提供方时返回 `transport_not_configured` 并保留原预览。模拟端口返回 `sent` 只更新测试发送状态，不建立入站就绪证明；未知结果保留原测试，禁止新预览替代发送。

诊断只构建当前授权资料域的本地允许字段预览。预览和下载受当前属主身份、会话及资料域授权约束，并绑定账户、调用者、认证代次、投影代次、修订、双水位和五分钟有效期。允许字段限于状态、时间和计数，不接受正文、日志、路径、密钥、凭据引用或生产执行身份；缺失或陈旧的事实保留 `unknown` / `null`。预览不会发送消息或上传资料。

下载复核已存档字节与当前投影，返回已预览的 JSON 原始字节和固定附件名。浏览器限制大小、校验附件类型及 SHA-256、严格校验允许字段和与预览的内容一致性，然后保存。无效摘要、额外字段、重复 JSON 属性、变更的投影代次、域授权撤回和过期预览均不能变成下载文件。迁移实际为 `0021_notifications.sql`，因为 `0020_http_sources.sql` 已由采集任务占用。
