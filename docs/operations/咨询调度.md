# 咨询调度与回执

服务宿主可在 `createApp` 中配置 `consultationWorker`，使用 Autoloop 的 `patrick-consultation` 专用 worker key。咨询请求与 `consultation.requested:<request_id>` 在同一事务落盘。调度按原事件 ID 重试，收到并保存 Hub 回执后确认本地 outbox；重复投递不会创建第二个咨询。

只有隔离执行器的实际准入、计费路线和费用上限都通过了核验，才为对应账户和资料域配置付费后端。没有合格后端时，可以核对 Hub 回执，不能领取付费工作。咨询只使用自己的 grant、预算及 `consultation:<request_id>` 发送键。关联的工作在等待本人回答时保持原状态。

发送后的恢复按持久证据处理：

- 有核验过的终态和用量回执：重启可补写最终答复，不重新获取发送许可。旧许可过期不影响保存已有结果。
- 只有发送许可，或用量无法核验：结果保持待核验，不重新发起付费调用。
- 本人已取消：迟到的付费结果只作为原咨询的回执保留，不覆盖取消，也不再生成最终答复消息。

HTTP 命令的业务变更与幂等回执同事务提交。网络断开后，可用同一个 `client_request_id`、同一目标及原请求重取命令回执，再读取当前咨询结果。更换目标或正文是冲突；读取回执时仍需拥有该资料域的权限。

MCP 宿主通过服务导出的 `createAuthenticatedConsultationMcp` 接入，只传入调用请求中的 Bearer 凭据。服务在解析目标后重查对应资料域的 `mcp:consult` 或 `mcp:memory` 权限，知识查询使用本地当前撤回水位。

本地回归使用隔离 SQLite、锁定的 Autoloop 实例与受控的执行器替身。真实模型计费、隔离设备和安装配置以 T09/T25 的准入证据为准。
