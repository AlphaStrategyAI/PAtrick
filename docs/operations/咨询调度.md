# 咨询调度与回执

服务宿主可在 `createApp` 中配置 `consultationWorker`，使用 Autoloop 的 `patrick-consultation` 专用 worker key。咨询请求与 `consultation.requested:<request_id>` 在同一事务落盘。调度按原事件 ID 重试；Hub 的接收回执和本地的派工确认分开处理。重复投递不会创建第二个咨询。

部署时把数据库和凭据目录放在固定的本机路径，重启沿用原路径。暂停 Autoloop 的「咨询」规则期间，Hub 会记住收到的事件，但不会创建运行。恢复规则后，由持有 Hub owner 权限的操作者按暂停起点执行该规则的补跑；不要为补跑创建新咨询。服务只在确认原事件已有对应运行时确认派工。

只有隔离执行器和固定单次费用的报价都通过了核验，才为对应账户和资料域配置付费后端。没有合格后端时，可以核对 Hub 回执，不能领取付费工作。领到其他资料域的咨询时，Hub 会安排原咨询稍后再调度，服务不为它创建付费预留。咨询只使用自己的 grant、预算及 `consultation:<request_id>` 发送键。关联的工作在等待本人回答时保持原状态。

发送后的恢复按持久证据处理：

- 有核验过的终态和用量回执：重启可补写最终答复，不重新获取发送许可。旧许可过期不影响保存已有结果。
- 已证实不可恢复的失败：核验用量后将原咨询推进至失败，保留回执，不生成答复消息。
- 只有发送许可，或用量无法核验：结果保持待核验，不重新发起付费调用。
- 本人已取消：迟到的付费结果只作为原咨询的回执保留，不覆盖取消，也不再生成最终答复消息。

运行中服务续租原 Hub 运行。最终回执用原运行凭据发送，凭据保存在凭据目录，业务库只持有引用。若提交回执后响应丢失，重启在凭据保留期内重送同一回执；没有凭据时保留未确认状态。

HTTP 命令的业务变更与幂等回执同事务提交。网络断开后，可用同一个 `client_request_id`、同一目标及原请求重取命令回执，再读取当前咨询结果。更换目标或正文是冲突；读取回执时仍需拥有该资料域的权限。

MCP 宿主通过服务导出的 `createAuthenticatedConsultationMcp` 接入，只传入调用请求中的 Bearer 凭据。允许的资料域和动作须同时在令牌签发范围和当前授权内；未绑定签发范围的旧令牌需要重新签发。调度时重查创建咨询时实际使用的权限，同一调用者的其他权限不能代替。历史队列若未记录是哪项权限授权，不能自动发送。知识查询使用本地当前撤回水位。

本地回归使用隔离 SQLite、锁定的 Autoloop 实例与受控的执行器替身。真实模型计费、隔离设备和安装配置以 T09/T25 的准入证据为准。
