# CLI 与 doctor 的有限交付范围

本增量提供 `deploy/cli/patrick.mjs` 的固定命令解析、可导入的 `createPatrickCli(host)` 组合接口，以及共用 `deploy/lib/doctor.mjs`。T23 的已安装 bootstrap、原生服务生命周期和双架构验收仍待交付。源码候选包的 `installable` 保持 `false`。

## 当前可以运行的入口

在仓库中运行 `node deploy/cli/patrick.mjs doctor` 可以读取当前 Node、平台、UID 等安全本地信息，并以 `HOST_REGISTRATION_REQUIRED` 和退出码 3 明确报告可信宿主登记缺口。此入口不会从任务工作目录、环境变量、JSON 或 SQL 自动加载宿主实现。单独导入该文件没有执行副作用。

安装后的可信控制器需要在进程内提供独立登记的 `RegisteredHost`；类型见 `deploy/lib/doctor.d.mts`。现阶段真实 T21/T22/T27 组件组合已在 Vitest 的 TypeScript loader 中验证，尚未证明独立 Node 安装包可运行整个服务图。运行构建必须处理 TS 导出、共享 authority 模块身份、迁移资产位置和目标架构的 SQLite 原生依赖。

## 固定命令与结果

命令集合为 `init`、`doctor`、`install`、`start`、`stop`、`backup`、`restore`、`upgrade`、`uninstall`。默认预览；`--preview`、`--execute`、`--readback` 互斥，执行或读回需要稳定的 `--operation`。doctor 仅读取观察值。选择值是已登记 ID，不能用路径、shell、模块或凭据建立权限。

| 命令 | 选择项 | 当前组合行为 |
| --- | --- | --- |
| doctor | `--vault ID` 可选 | 汇总本地、T21 网络、T27 Vault 和已登记的恢复记录观察值 |
| init | `--vault ID --operation ID` | 实时 Vault 端口、独占 owner 和日志签名器齐备时可预览；执行需签名批准，含原计划的登记可验证读回 |
| backup | `--target ID` | 真实 T22 签名 reserve/run/read；同 ID 已完成结果直接读回 |
| restore | `--target ID --manifest SHA256`，可选 `--mode drill` | 默认隔离恢复演练，使用真实 T22 算法和签名读回 |
| install / upgrade | `--release ID` | 在可信独占 staging 中执行真实发布验证；当前候选不能安装 |
| start / stop / uninstall | 无资源路径选择项 | 明确报告缺少的安装、排空、写者围栏和进程读回能力 |

备份和演练在可信登记齐备的 factory 中可执行。完成状态来自已认证的恢复记录；未知结果保持 `uncertain`，再次执行或读回不会重复未知副作用。隔离演练不会恢复生产写入许可。T27 的 create-only 安装器现可由已安装 CLI 的 Vault 初始化控制器组合。可信宿主在进程内登记操作和持久日志，并提供受控独占 owner；固定读回器验证签名日志并在该范围内独立观察实际文件。执行需要保留的签名批准。仅验证读回使用原计划、公开验证登记和受控锁，不需要持有批准签名或日志签名器。CLI 的 ID 参数本身不授予这些能力。

JSON 退出码：0 表示有限操作完成或预览；2 为参数无效；3 为前提缺失；4 为结果未知；5 为受阻；6 为尚无结果或已预留。命令不能凭本地备份或演练完成声明异地保护、恢复激活或公司权限已就绪。

## 诊断证据与限制

doctor 每项提供状态、受限且脱敏的证据、观察时间、影响范围和下一步。核心服务、任务前提、可选编辑器和通道分别报告。UID/主机身份和数据目录检查使用真实本地探针；网络探针保留 TLS 验证并绑定登记 origin/RP ID。Vault 观察沿用同一账户、域、设备、scope 和配置版本。

聚合探针有五秒响应期限，并在 API 支持时传递取消信号。忽略取消的可信旧适配器可能在超时后继续运行，因此聚合超时不构成资源已排空的证据。文件探测不能证明原生组件实际可启动。本节所述早期 doctor 测试使用合成 inspector；后续桌面端实测范围见 [Obsidian 接入报告](obsidian-install-report.md)。

发布验证要求宿主独立提供物理 staging 根，并在整个检查期间独占树及祖先。Node 路径检查不能解决敌对替换后复原的 ABA 情况；相关范围和条目预算见 `release-report.md`。

## 已验证范围

当前冻结版本的 CLI/doctor 定向验证包含 84 个用例，覆盖真实临时 SQLite 恢复、同 ID 重放、未知结果不重做、签名篡改拒绝、T27 kit、实际 loopback TLS 拒绝及脱敏输出。发布组件保留此前同一源码通过的 35 项回归证据。另执行 scoped lint、根和 Web typecheck、两个入口的 Node 语法检查。临时证据保存在 `/private/tmp/patrick-plan-continuation-20261117/T23-cli-*`。

首次独立复审发现恢复目标和 doctor 登记可能在异步等待期间替换，导致沿用旧身份判断。修复为捕获固定普通配置、保留实际组件句柄，并在各次等待后、最终调用前和结果投影前重新核对当前登记。新增 21 个变更场景覆盖恢复读回/预留/最终绑定、网络/Vault/就绪探针、发布 staging 和 kit。已经产生签名 claim 的未知结果继续保持未知，读回不重复执行。原失败复审及红测证据完整保留。

第二轮复审发现 `init` 在诊断因身份变化提前返回时可能读取缺失的 Vault 检查，以及配置捕获拒绝可能绕过命令回执。修复为接受部分诊断报告，并在公开 `run` 入口将捕获拒绝转换为固定、脱敏且可序列化的受阻结果。新增 18 项先失败再通过的回归覆盖九个命令、预览/执行/读回和已签名 claim；已声明但未确定完成的恢复操作仍返回 `uncertain`，不重做副作用。相关失败复审及对应证据均保留。

第三轮复审发现公开身份结果会包含登记对象的额外元数据。CLI 和直接 doctor 现共用严格的五字段身份投影，并校验标识长度、资料域数量及唯一性；私有签名绑定与实时配置变更检查仍使用完整登记。新增 14 项先失败再通过的用例覆盖九个命令、部分诊断、签名恢复重放和超大敏感元数据，确认公开 JSON 不包含这些额外字段。

初始 parser RED 的路径设置错误，不能算作有效行为红测；后续各项有真实断言失败证据。整个 T23 需继续完成构建/登记、安装升级卸载、原生重启与最终候选验收。

## 2026-11-18 已安装 Vault 初始化验证

可信宿主按操作 ID 登记 Vault 初始化后，`init --vault ID --operation ID` 可选择 `--preview`、`--execute` 或 `--readback`。预览需要实时 Vault 端口、独占 owner 和日志签名器，并产生绑定身份、资料域、设备、配置和物理目标的计划；执行需要宿主保留的签名批准。初始化只补缺项，独立观察和签名日志用于读回；发布后失去确定性时返回 `uncertain`，不自动重放副作用。命令行不接收任意路径、计划或签名来建立权限。

此增量在当前分支父版本以官方 Node 24.9.0 运行 284 项关联测试和 48 项构建测试，均无跳过；独立复审还核对了两种安装材料中的 12 个普通 Node 合成场景和签名日志。测试使用合成 Vault 与登记，不代表本人真实 Vault、生产安装、主机重启或断电持久性已验收。
