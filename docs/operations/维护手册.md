# PAtrick 试点维护手册

## 开始试点

在首次真实调用前，冻结一个工作范围和一个标准域，登记版本、权限边界、预算、停止条件，以及至少 10 个种子案例和 5 个独立留出案例。每项工作保留来源修订、工作 ID 与代次、标准和证据版本、授权及回执引用。优先复核直接交付、本人答复后续办、过期或冲突后受阻这三条工作线路。[验收计划](../plans/PAtrick技术实现计划.md#t25-真实纵向闭环与故障演练)

引用准确率的初始目标为 95%。一例经核实的越权、应问未问或受控检索召回已撤回材料，即暂停扩展并复核原始工作和授权证据。付费调用只从已批准的试点预算扣除，重试和更换后端沿用原预算。[验收计划](../plans/PAtrick技术实现计划.md#83-最终交付证据)

## 每周维护

在同一试点范围每周留一份维护记录。记录实际开始和结束时间、本人投入、影响的工作、故障类别及其证据引用。每周计划时间为 60 分钟。连续两周超过 60 分钟时暂停扩展，记录最高频的故障，并为后续处置指派负责人和期限。缺少某周记录时保留未知，补齐观察后再判断是否连续超时。

1. 在系统页查看服务、网络、执行器、投影及渠道状态；需要定位时查看 `doctor` 的具体检查项和观察时间。对照同一账号、资料域、设备和配置修订，再处理阻塞。对账中或未确认的外部操作按原操作 ID 或投递标识读回。
2. 回看本周生效标准与候选的差异，标出变化涉及的案例、引用和评测证据。正在运行的工作沿用发起时的标准修订。记录升级候选版本、签名状态、schema 范围及同一构建摘要对应的验收结果。[候选包记录](release-report.md)
3. 核对委托权限、到期状态和资源预算变化；记录已撤回的授权及仍待对账的效果。查看系统事件、需本人确认项和飞书收发状态。实际通知维护使用已登记的 Autoloop 规则和专用 worker；标准、升级、委托和系统事件的周汇总仍待真实试点留证。[通知维护记录](notifications-diagnostics-report.md)
4. 按工作 ID 取最新权威终态后统计。失败、取消、转人工和未观测结果均保留。记录引用准确率、成果有效率、返工、关键失误、本人介入时间及授权范围内自动完成率，逐项附分母、实际样本数及未知情况。成果还未经过观察时标记 `unknown`。[统计口径与证据](stats-report.md)

## 发布复核

每项任务在发布证据清单中登记证据路径、完成日期、版本、实际运行身份及命令退出码。截图和录屏仅收录获准样例或脱敏数据，排除真实凭据。缺真实设备、通道或目标仓库证据的场景标为 `blocked`。保留失败和豁免记录。P0、P1 完成处置后才通过发布门槛，P2 须有具名负责人和到期日。[证据合同](../plans/PAtrick技术实现计划.md#83-最终交付证据)

使用 `node scripts/check-release-evidence.mjs "$EVIDENCE_DIR"` 核对已列出的场景状态和通过场景的证据摘要。逐项复核清单的完整性及真实验收范围，再核对本次发布的双架构包和 T25 通过验收的最终签名 envelope 摘要一致。发布后取回两份资产，依据独立登记的公钥与签名策略重新核验。[双架构构建与验签](release-report.md)

采集发布证据时，将 `PATRICK_PILOT_FACTS` 指向已复核并脱敏的试点事实 JSON。T26 会汇总范围内已观察的终态，并记录各指标的样本量和未知值。缺少文件路径时，试点结果保持 `pending`。

核对真实提供者回执及授权后，将 `PATRICK_T25_REVIEWED_TRACES` 指向三条 `PilotTrace` 的 JSON 数组，依次为直接交付、答后续办、过期或冲突拦截。证据引用以该文件所在目录为根。采集器校验三条线路与证据摘要，并在发布证据中记录引用和清单摘要。
