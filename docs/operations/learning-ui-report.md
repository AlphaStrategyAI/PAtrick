# T16 知识、标准与委托验收

知识列表和搜索先限制到账户及资料域。界面保留事实来源、版本和冲突；原稿登记与新稿补充是不同动作，目标由 Vault 数据确认。登记后可查看实际文件位置和独立的文件、业务、导回状态。没有已核验绑定时只显示相对路径。

标准界面区分当前、历史、候选、退化与评测证据。采纳路由把已提交的版本交给同一 Vault 投影器，批次不包含原稿或评测样本。在隔离 Vault 中用实际文件阻塞首次导回，业务仍显示已采用。重试使用同一采用事实、导回意图、投影版本和冻结字节；如果索引可能已发布，先核验现有索引和批次，再确认回执。重试不会重新评测、重新采用或创建新工作。批次目录越界时拒绝写入；原批次只有在新索引通过核验且旧文件已保全后才可移除。

如果内容存储暂不可用，已冻结的内容会保存在数据库中，编辑回执显示导回待重试。内容存储恢复后用原冻结数据续办。较新的已发布批次接替旧的未完成导回时，旧回执保留原采纳事实，并记录接替它的批次。

委托页面先显示当前范围和预期变化。只打开预览不会产生写入；登记提案冻结具体委托、命令、范围、修订、授权配置和 T03 挑战，登记或单独确认均不会变更状态。应用时核对同一调用者、可写资料域、当前政策、修订和受信回执，再在同一个写事务中执行并记下结果。版本冲突、过期、没有可信回执或回执不属于这条提案都不会变更委托。本地浏览器确认流程使用 T03 的已认证近期会话与一次性挑战，不声称每次动作均重新通过一次 WebAuthn 签名。

浏览器验证使用锁定 Chromium、合成账号及 Vault、真实本地 HTTP 处理器和 SQLite 无外部动作。真实 Obsidian 桌面、提供方凭据和原生运行仍在各自实机任务中验收。
