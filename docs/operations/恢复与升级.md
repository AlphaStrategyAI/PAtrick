# PAtrick 恢复与升级

## 备份与只读核验

每日生成本地 RecoverySet。在可信宿主登记中选择备份目标和稳定操作 ID，核对目标有权保管本次快照中的全部资料域。在标明备份与恢复资源所有者后，完成入口排空和实际写者冻结，再由登记签名端口生成 RecoverySet。T22 集合核验服务库、Hub 库、资源清单、schema、撤回水位及文件摘要。[T22 恢复记录](recovery-report.md)

离机备份默认关闭。维护登记可省略 `plan.protection`，只读核验登记也可省略 `protection`，两处均按 `local_only` 处理。启用离机备份时，维护登记指定 `off_host_required` 并提供备份端口与保护核验器，只读登记指定 `off_host` 并提供核验器。启用后需保留加密目标的读回回执和独立恢复凭据引用。

已安装服务的维护切面还需核验单独的本地答案库交接。核对与同一 RecoverySet manifest 绑定的签名 `local-answers.sqlite` 交接、登记切面身份和文件摘要，并将它与运行 Autoloop 的 Hub 库分别读回。只有三方实际交接均已核验，才继续升级选择。[服务连接与所有权](runtime-drain-report.md)

从可信控制器用同一个目标及操作 ID 读回原签名记录。`doctor` 的本地备份就绪要求已登记的完成操作及对应 manifest 摘要可核验。只剩验证端口时，仍可检查已存在的本地备份。离机保护未配置时显示 `not_configured`，已配置时由独立读回证明保护状态。若持久 claim 已存在且没有可核验的终态，维持 `uncertain`，先对账原操作。[CLI 状态及退出码](cli-report.md)

## 隔离恢复演练

1. 登记隔离主机、目标版本和新数据根。记录计时起点、事件或中断时间、备份快照水位以及当时可确认的撤回水位。将下列参数交给已登记的可信控制器，`TARGET_ID`、`MANIFEST_SHA256`、`OPERATION_ID` 分别替换为已登记的目标、签名 manifest 摘要和稳定操作 ID。

   ```text
   restore --target TARGET_ID --manifest MANIFEST_SHA256 --mode drill --execute --operation OPERATION_ID
   restore --target TARGET_ID --manifest MANIFEST_SHA256 --mode drill --readback --operation OPERATION_ID
   ```

   用读回取得同一操作的签名终态，核对状态 `completed`、原 manifest 摘要及 `externalWrites` 为零后再记录演练耗时。
2. 在隔离库读回签名备份、独立见证及完整撤回链。保留较新的原稿；文件冲突留下原路径、修订及核对结果。检查投影已重建，来源暂停，旧 Web 会话、派工授权和飞书回调受到围栏限制，飞书进入待重新授权状态。[隔离恢复检查](recovery-report.md)
3. 对账未决咨询和外部效果。记录各阶段完成时间、阻塞域、RPO 和 RTO。以中断点和已证实可恢复的数据点衡量 RPO，以恢复所需的实际时长衡量 RTO。目标分别为 24 小时以内和 2 小时以内。测试缺阶段或缺可靠时间时保留未知；撤回后的召回门禁按当前撤回水位核对。[恢复目标与撤回证明](../plans/PAtrick技术实现计划.md#64-备份恢复与升级)

见证仍处于 `open`、不可达或缺少完整撤回证明时，保留相关域关闭，核对独立控制记录。本人经可信控制导入幸存原稿的路径使用新 epoch，单独计时。正式切换须先核验当前封存证书、精确封存修订、旧写者停止及凭据撤销。候选用该修订向独立见证执行一次 CAS，并读回自身赢得的新 epoch、唯一激活 ID 和父封存修订。确认丢失时按同一激活 ID 读回。结果待定或其他候选获胜时维持该域关闭。[见证及本人导入](recovery-report.md)

## 升级与回退

1. 记录原发布和数据代次、候选签名包摘要、目标架构、运行时 ABI 和兼容 schema。独立确认受控 staging、磁盘余量、固定 HTTPS origin 及当前服务身份。
2. 暂停新派工，排空并保持写者围栏。核验签名备份及本地答案库交接后，在隔离数据代次执行迁移与合同回放，记录水位和撤回链。完成候选验证和研究灰度后提交绑定发布和数据代次的选择。只有独立代次读回确认精确的发布摘要、数据代次及无待定选择，同时候选已赢得独立见证的 CAS，才开放新写者。确认丢失时以同一操作 ID 读回，尚待确认的选择继续保持写者围栏。随后复核已登记服务状态、数据范围和当前写者。[构建交接](runtime-build-report.md)
3. 回退旧程序和旧库前，取得经过核验的备份、当前写者已经停止的证明，以及切换后写入数确为零的证据。有新写入或写入情况未知时保留当前数据，走通过验证的前向或逆向迁移。卸载按登记所有权停止和移除服务资源，保留业务数据、Vault、本人原稿和共享凭据。[升级与保全规则](../plans/PAtrick技术实现计划.md#t23-总安装器和升级)

当前可在可信登记齐备时使用本地备份、隔离演练和签名读回。目标主机的安装、切换及回退计时、正式写者交接和原生重启仍待验收。已启用离机备份的部署应另外验证远端读回和恢复。接入流程与本地测试证据见 [CLI 记录](cli-report.md) 和 [发布包记录](release-report.md)。
